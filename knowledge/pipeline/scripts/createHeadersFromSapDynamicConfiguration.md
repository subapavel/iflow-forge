## Gotchas

- Any exception while collecting the properties is caught and ignored [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L19] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L20]; the headers for the properties collected before it are still written [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L23] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L25].
- No matching property: no header is set [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L23].
- The prefix is cut with `replaceFirst("^SapDynamicConfiguration_", "")` and the header prefix `dc_` + `SapDynamicConfiguration_` is put back, so the header name is "dc_" plus the property name [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L7] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L16] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L25].
- In Step01 XI no setter of a `SapDynamicConfiguration_*` property is in the label: a grep of every script and `.iflw` of the label for the prefix finds only this script [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L5] and the Step08 XI mirror, which sets such properties itself [com.sap.integration.cloud.pipeline.v2.generic.step08.outbound.processing.xi, scripts/createSapDynamicConfigurationFromHeaders.groovy#L26]. The comment calls it the "Property Prefix for Dynamic Configuration" [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/createHeadersFromSapDynamicConfiguration.groovy#L4], and SAP's change log says the XI inbound flow supports dynamic adapter specific configuration since 1.0.5 [generic-inbound/CHANGELOG.txt#L14] [generic-inbound/CHANGELOG.txt#L17]; which component sets the properties on an incoming XI message is an open question (open-questions/kb-06.md).
- Downstream, the Step02 to Step05 generic iFlows admit headers matching `dc(.*)` [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, property "allowedHeaderList"] [com.sap.integration.cloud.pipeline.v2.generic.step02.integrated.messaging.async, property "allowedHeaderList"] [com.sap.integration.cloud.pipeline.v2.generic.step02.integrated.messaging.sync, property "allowedHeaderList"] [com.sap.integration.cloud.pipeline.v2.generic.step04.receiver.determination, property "allowedHeaderList"] [com.sap.integration.cloud.pipeline.v2.generic.step05.interface.determination, property "allowedHeaderList"]; the mirror script `createSapDynamicConfigurationFromHeaders.groovy` in Step08 XI reads the same header prefix [com.sap.integration.cloud.pipeline.v2.generic.step08.outbound.processing.xi, scripts/createSapDynamicConfigurationFromHeaders.groovy#L7].
