Draft claims and attribute values of KB-11 (overview.md, scenario-contribution.md) that no artifact of 2026-06 or 2026-09 settles: what is unknown, what the artifact shows, what would answer it.

- **A new partner without deployment.** Unknown: whether a new sender or partner for an existing message type needs only Partner Directory entries. The artifacts read scenario data under the partner ID [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L342] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/readBypassOptionFromPD.groovy#L22] and take the Step07 address from the Service of an Interface entry [com.sap.integration.cloud.pipeline.v2.generic.step05.interface.determination, step 47 "Get interface"]; whether an existing Step07 copy fits the new partner is tenant configuration. Would answer: a tenant run or SAP's documentation.
- **Generic iFlows deployed once.** Unknown: that each generic iFlow runs once per tenant, unchanged. The artifacts bind tenant-level parameters such as the queue prefix [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, parameter "PipelinePrefix"] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, parameter "PipelineJMSQueuePrefix"], and SAP's change log names "setting up multiple pipelines" [generic-pipelines/CHANGELOG.txt#L30], so more than one deployment per tenant is foreseen. Would answer: SAP's deployment guidance.
- **Exception handling of the templates.** The draft says every template ends its exception handling with custom status RetryViaParentFlow and the calling generic step owns the retry. Of the 18 template .iflw files, 13 set it, e.g. [com.sap.integration.cloud.pipeline.v2.template.step07.outbound.processing.p2p, step 6 "Set custom status"]; alo, eo, Step01 sync, Step07 sync and custom.error.handling do not, and a grep of both labels outside templates/ finds RetryViaParentFlow in no generic iFlow or script. The caller's retry gateway tests only SAPJMSRetries and maxJMSRetries [com.sap.integration.cloud.pipeline.v2.generic.step06.outbound.processing, step 17 "Max # of retries reached?"]. Unknown: whether an exception in a template called by ProcessDirect reaches the caller's exception subprocess at runtime. Would answer: a runtime test.
- **EOIO.** Unknown: how an EOIO scenario runs on the pipeline.
