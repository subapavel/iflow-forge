# Migration: PO ICO to pipeline

From one PO Integrated Configuration (ICO) to an approved pipeline scenario on the `2026-06` fact base; attributes per D-025. It reports ICO content and pipeline needs; no ICO assessment. Human decisions and defaults: migration/variants.md.

## Inputs

- ICO JSON: `po-xray ico -s <system> -c <component> -f json` (`--direction` in | out | both, default both, out = the component sends). The file `icos-<component>.json` holds the record `IntegrationInventory` (`io.poxray.json.Json`): field names = record component names, null and empty fields omitted (absent `condition` = no condition).
- This knowledge base: scenario-contribution.md, partner-directory.md, conversion/README.md, migration/variants.md.
- Tenant profile (part 2): not yet available; tenant values stay naming.md placeholders.
- Tenant package versions: versions/features.md "The tenant's installed version".

## Steps

1. Read the ICO JSON: one `icos[]` entry → the proposal's Source summary:
   - `icos[].sender`: `party`, `component`, `iface` (`name`, `namespace`), `operations[]`, `channel` (`party`, `component`, `name`);
   - `icos[].receivers[]`: `party`, `component`, `qualityOfService`, `condition` (`text`, `lines[]` with `group`, `left`, `operator`, `right`), `channels[]`, `interfaces[]` (`operation`, `condition`, `mapping`, `targets[]` with `iface` and `multiplicity`, `parameters`). The JSON gives `condition.lines` prefixes no namespace: take them from the sender message type (`esr.serviceInterfaces[].operations[].request`) or ask. The XSLT result's `Receivers` is in namespace `http://sap.com/xi/XI/System` [com.sap.integration.cloud.pipeline.v2.generic.step02.integrated.messaging.async, step 59 "Any Receiver?"] [com.sap.integration.cloud.pipeline.v2.generic.step04.receiver.determination, resource "xsd/Receivers.xsd"];
   - `icos[].dynamicRouting` (`operationSpecific`, `mappings[]`); `icos[].noReceiverBehaviour` (configuration, not an attribute): the XSLT result's `ReceiverNotDetermined/Type`, by migration/variants.md "No receiver found";
   - `channels[]`: `id` (`party`, `component`, `name`), `direction`, `adapter` (`<transportProtocol>/<messageProtocol>`), `transportProtocol`, `messageProtocol`, `attributes`, `modules[]`;
   - `esr.operationMappings[]` whose `id` equals an `interfaces[].mapping`, with `steps[]`; `esr.messageMappings[]` (`multiplicity`); `esr.importedArchives[]`; `esr.serviceInterfaces[]` (`operations[].mode`).
2. Derive attributes: Source summary → one value each; unresolved → Open questions.
   - Sender alias and partner ID (migration/variants.md), human confirms: XI, what determinePartnerID derives from headers SAP_SenderAlias, SAP_Sender [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/determinePartnerID.groovy#L155] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/determinePartnerID.groovy#L165], default the sender component (SAP_Sender = sapsenderservice) [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, step 1 "Set SAP headers"] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/determinePartnerID.groovy#L241]; XI partner ID, in this order: alternative partner (agency, SAP_SenderInterface, SAP_SenderInterfaceNamespace) [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/determinePartnerID.groovy#L323], then (agency, `SenderInterface`, SAP_SenderInterface) [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/determinePartnerID.groovy#L327], else `<agency>~<SAP_SenderInterface>` [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, scripts/determinePartnerID.groovy#L338]; IDoc, what determinePartnerIDForIDocInbound derives from the control record [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L31], default the sender's logical system [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L208] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L294].
3. Fill migration/proposal-template.md: attribute values, Source summary → every section.
4. Obtain human approval: the proposal → Status approved, named and dated. Nothing is generated without it; open questions block it.
5. Produce artifacts: the approved proposal → what scenario-contribution.md "What a scenario contributes" lists, checked against its "What a scenario must not touch".
6. Convert modules and mappings per conversion/README.md: sender and receiver `channels[].modules[]` (`position`, `name`, `type`, `namespace`, `parameters`) and the mapping programs (`esr.operationMappings[].steps[]` with `kind` request | response | fault and `program`: `type` XI_TRAFO message mapping, MAP_ARCHIVE_PRG Java mapping, class in its `program`; `esr.importedArchives[].programs[]` with `kind` javaMapping | class | xslt | javaSource, `mappingApi`, `text`) → one Conversions needed row each, with its recipe.
7. Append to the knowledge base: last section.
