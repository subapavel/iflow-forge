# Partner Directory

How the pipeline artifacts of `2026-06-trial` name, read and fall back on Partner Directory entries. Header names on this page are listed in contracts.md; here are the keys.

## Key scheme

- The Partner ID (PID) is the configuration scenario: header partnerID [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L342] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L603]; a partnerID already present is kept [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L312].
- determinePartnerID: agency `<party>.<sender alias>` or `<sender alias>` [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L318]; alternative partner (agency, `<SAP_SenderInterface>`, `<SAP_SenderInterfaceNamespace>`) [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L323], then (agency, `SenderInterface`, `<SAP_SenderInterface>`) [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L327]; else PID `<agency>~<SAP_SenderInterface>` with `&`, `%`, `/` replaced by `_` [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L338], unless CustomXPid_SwitchOffTilde is "true", which throws IllegalStateException [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L332] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L333].
- An alternative-partner triple (agency, scheme, id) is unique per tenant, so a sender interface resolves to exactly one partner ID [owner, 2026-10-20].
- determinePartnerIDForIDocInbound: sender alias = alternative partner (`<tenantStage>`, `LogicalSystemName`, `<logical system>`), else with SNDPRN [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L437] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L442]; agency `<sender alias or logical system>` for partner type LS, else `<party alias or ALE#<SNDPRT>[#<SNDPFC>]#<SNDPRN>>.<sender alias or logical system>` [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L550] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L558]; with CustomXPid_ResolveVirtualReceiver "true" first `<agency>:<receiver>` [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L528]; per agency the two interface lookups, the interface with `&`, `%`, `/` replaced by `_` as scheme [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L748] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L756]; then sender system only and SNDPRN as agency for partner types other than LS [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L568] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L575]; then the tilde PID unless switched off [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L586]; else IllegalStateException [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L599].
- Stages: PID `SAP_Integration_Suite_Landscape`, parameter `{{tenant.name}}` (environment TENANT_NAME), default "PRD" [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L22], value a comma-separated stage list [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L23]; the stage is the agency of alias lookups, e.g. receiver business system = alternative partner (`<tenantStage or PRD>`, `BusinessSystemName`, `<receiver alias>`) [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/mapReceiverAliasToBusinessSystemName.groovy#L32] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/mapReceiverAliasToBusinessSystemName.groovy#L36].

## Value types

- String parameters: `getParameter(<key>, <PID>, String)` in every reader below, e.g. [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/readInboundQueueFromPD.groovy#L21].
- Binary parameters: an XSLT mapping whose header XSLTMapping is `pd:<partnerID>:<key>:Binary` [com.sap.integration.cloud.pipeline.v2.generic.step04.receiver.determination, step 36 "Get XSLT mapping from Partner Directory"], used as mapping source of the next step [com.sap.integration.cloud.pipeline.v2.generic.step04.receiver.determination, step 37 "XSLT Mapping"]; no Groovy script calls getBinaryParameter (grep of every Groovy script). Binary parameters let the generic steps run a scenario's XSLT without a scenario-specific iFlow [rationale, from analysis 2026].
- Alternative partners: `getPartnerId(<agency>, <scheme>, <id>)` and `getAlternativePartnerId` [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L327] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/mapReceiverAliasToBusinessSystemName.groovy#L36]; authorized users: `getPartnerIdOfAuthorizedUser` [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L374].

## Behaviour when a key is missing

- No Partner Directory service: IllegalStateException "Partner Directory Service not found" in the read…FromPD scripts, determinePartnerID, determinePartnerIDForIDocInbound and mapReceiverAliasToBusinessSystemName [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/readCustomXFromPD.groovy#L14] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/determinePartnerID.groovy#L63] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/determinePartnerIDForIDocInbound.groovy#L64] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/mapReceiverAliasToBusinessSystemName.groovy#L28], "not available" in mapSenderStageToReceiverStage [com.sap.integration.cloud.pipeline.v2.generic.step04.receiver.determination, scripts/mapSenderStageToReceiverStage.groovy#L281]; the Step08 scripts and setPropertyFromPdStringParameter return the message unchanged [com.sap.integration.cloud.pipeline.v2.generic.step08.outbound.processing.idoc, scripts/setAllDefaultAndScenarioValuesFromPDForIDoc.groovy#L31] [com.sap.integration.cloud.pipeline.v2.generic.step08.outbound.processing.xi, scripts/readPDValuesForXI.groovy#L42] [com.sap.integration.cloud.pipeline.v2.script.collection, scripts/setPropertyFromPdStringParameter.groovy#L15].
- No header partnerID: IllegalStateException "Partner ID not found in sent message" in the read…FromPD scripts [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/readCustomXFromPD.groovy#L21], except in readReceiverSpecificQueueFromPD, which reads it without a check [com.sap.integration.cloud.pipeline.v2.generic.step04.receiver.determination, scripts/readReceiverSpecificQueueFromPD.groovy#L18].
- Missing value: most readers write the property as null with `?: null` [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, scripts/readInboundQueueFromPD.groovy#L25] or a default ('false', 5, 'Error'); readCustomXFromPD and the Step08 scripts set nothing [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/readCustomXFromPD.groovy#L52] [com.sap.integration.cloud.pipeline.v2.generic.step08.outbound.processing.xi, scripts/readPDValuesForXI.groovy#L50].
- `InboundQueue` missing, prefix + DefaultJMSQueueNumber [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, step 30 "Which queue?"] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, step 34 "Which queue?"]: the artifacts state no default prefix; `parameters.prop` is never staged [knowledge/sources/README.md#L14], and the descriptions of PipelinePrefix (1X) and DefaultJMSQueuePrefix (1I) say only "Change the prefix if you like to setup an additional pipeline" [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.xi, resource "parameters.propdef"] [com.sap.integration.cloud.pipeline.v2.generic.step01.inbound.processing.idoc, resource "parameters.propdef"].
- Header first: `<CustomXType>Enabled`/`Endpoint`, customXInboundConversionEndpoint, customXRDEndpoint and maxJMSRetries headers win over the Partner Directory [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/readCustomXFromPD.groovy#L38] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/readInboundConversionFromPD.groovy#L22] [com.sap.integration.cloud.pipeline.v2.generic.step04.receiver.determination, scripts/readCustomReceiverDeterminationFromPD.groovy#L21] [com.sap.integration.cloud.pipeline.v2.generic.step02.inbound.processing, scripts/readRetryHandlingFromPD.groovy#L21].
