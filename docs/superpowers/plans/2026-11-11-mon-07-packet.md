## Rules

- QA only, read only, under the owner's configured QA system file in `~/.po-xray/systems/`. No call
  to PROD or DEV, no `--save` outside the private directory, no resend/cancel (the code has none).
- Every command's full output goes to `local/<customer>/monitoring-acceptance/` (gitignored). The
  tracked run log `target/mon-07/run.log` and the hand-back carry only commands with placeholders
  (`<qa>`, `<iface>`, `<ns>`, `<id>`), exit codes, counts and neutral shapes (e.g. "key = 3 parts
  separated by `\`"), never hostnames, users, component/interface names, IDs or payload text.
- Time window small (`--from -7d` at most) and `--limit` ≤ 50.

## Checks (verifier, built jars `po-xray-cli/target/po-xray-cli-*-runner.jar`, `po-xray-mcp/...`)

1. `messages lookup status-details` — the list of status codes/labels (labels are SAP's, may be
   reported); `messages lookup interfaces` — count only.
2. `messages search --faulty --from -7d --limit 50 --json` — count, statuses seen, whether
   `moreAvailable`; key format shape; whether messages with `timesFailed`/`retries` > 0 or
   `wasEdited`/archived appear (do the required false/0 filter defaults narrow?); same window
   without `--faulty`, and with `--status <one code from 1>` — counts.
3. For one found faulty message: `messages log <id>` (entries count, `logLocations`/version fields
   seen), `messages payload <id>` (parts: count, content types, whether part 0 is the XI header),
   and `payload --version <v>` / logged variant for the values the log shows — which are accepted.
4. Whether `search` with only `--from` (no `--to`) is accepted; the request's `Locale` with 3
   children causes no fault on lookups with `--lang en`.
5. `messages uds-filters` — count; for one interface that has filters, `uds-attributes <id>` and
   one `uds-search` with one `name=value` — counts and exit codes.
6. MCP smoke: start the MCP runner jar over stdio, `initialize`, `tools/list` (11 `message_*`
   tools), and `tools/call message_search` with `statuses` as a JSON array of one code and a 1-day
   window — does the array bind (no argument error)? If the stdio exchange cannot be driven with a
   one-line command, report `NOT_RUN` with the reason.
7. Note any SOAP fault (its exception type and code only), any role/authorisation error, and
   anything that contradicts F-17 or the MON-02..06 behaviour.

## Hand-back

≤ 40 lines, neutral only, per check: command (placeholders), exit code, observed counts/shapes,
private output path. No judgement; contradictions reported as observed.
