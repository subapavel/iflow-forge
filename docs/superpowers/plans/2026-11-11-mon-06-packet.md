## Acceptance spec

A. Plan Task MON-06 as written (11 tools, parameters mirroring the CLI, `system` optional,
`includeRaw` false, `limit` 50, payload `part`/`offset` 0/`maxChars` 20000 with `totalChars` and
`truncated`, `McpBudget.fit` → `FittedSearch`, native registration, Step 1 tests) — with:

B. `saveDir` exists only on `message_log`, `message_payload`, `message_uds_attributes` (spec §7);
exactly these three have `readOnlyHint=false`; the other eight `readOnlyHint=true`; all eleven
`openWorldHint=true`. Saving goes through `MessageArchive.save` (which applies `SaveTarget`); a
refused target sends no request.

C. Environment seam (MON-05 carry): the monitoring tools resolve the system with
`MonitoringSystems.resolve(system, env, home)` and load it with
`PoSystem.load(name, PoSystem.defaultDirectory(), env)`, where `env` comes from a new
`@ApplicationScoped` bean `io.poxray.mcp.MonitoringEnvironment` (`Map<String,String> env()`,
production `System.getenv()`); tests replace it with a test-source `@io.quarkus.test.Mock` subclass
using the per-test system-property override pattern of the CLI tests. The existing `Inventories`
(`PoSystem.load(name)`) is not changed by this task. A cached `MonitoringClient` per system name is
allowed; the cache key includes nothing secret.

D. No temp file: monitoring tools never use the existing `ResultFile` spill; a test asserts that
`<java.io.tmpdir>/po-xray` gains no file during the oversized-search test. The 80,000-character cap
applies to the serialised tool result.

E. Ambiguity / not found / errors: `message_log`, `message_payload`, `message_uds_attributes`
given an ambiguous ID return the candidates (key or `null` with `"keyless": true`, direction,
receiver, status) and a hint, not an error; `NotFound` returns its reason; a `MonitoringException`
becomes a tool error with its one-line message (existing `call()` / `ToolCallException` pattern),
never a stack trace or password.

F. Descriptions: each tool description says it is read-only against the PO system (or, for the
three, "writes only when saveDir is given"), and the search tools tell the agent to call
`message_lookup` / `message_uds_filters` first for valid filter values.

G. Native: every record in `io.poxray.monitoring` reachable from a tool result is registered in
`NativeReflection`; `NativeReflectionTest` asserts all public records of the package are present.

H. Context7 for the Quarkus MCP server `@Tool`, `@ToolArg`, `@Tool.Annotations` before code; if
unavailable, `javap` on the resolved jar decides; follow `PoXrayTools` style.
