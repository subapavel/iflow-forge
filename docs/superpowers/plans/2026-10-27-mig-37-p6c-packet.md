## Architectural decision (draft — review at hand-over, D-056)

Private-only local evidence cite `[evidence: <use-id>]`; `<use-id>` is a dossier v3 `evidence-use` event ID.
- Where: only in private `plan.md` and `scenario-<k>.md` statements that belong to the exact proposal section the use
  names (Dependency decisionId, sectionId, revision, sha256). In `questions.md` a use may be listed as option evidence
  when its scope is the affected section's current proposed revision; it never answers the question. `analysis.md`
  does not use the form.
- When: the dossier is opt-in v3 and `po-xray dossier-check <dossier.json> --readiness` reports that use `supported`.
  Without a v3 dossier, or with any other state, the statement is uncited and opens a question as today.
- Text: the cited sentence reproduces the use text verbatim (which equals the packet claim text). Consequences are
  separate sentences that cite a decision `Q-<n>` or a page. A visible "KB difference" note stays when the KB says
  otherwise or is silent.
- Order (the scope sha256 is the snapshot's raw bytes, and a use and its packet claim need a proposal that already
  exists): choose the use ID; write the section snapshot containing the cited sentence and `[evidence: <use-id>]`;
  `propose`; prepare the packet whose claim scope is that proposal; independent review; `evidence-register`;
  `evidence-use` with the chosen ID; run the readiness check; only then show the round. Editing the sentence later
  creates a new revision: new packet claim scope, review, registration and use. `replaces` works only within the same
  exact scope.
- Committed pages show the form only with `<…>`, never a concrete ID. The public cite checker (Checks.java) is
  unchanged and never reads private packets. Generalising a packet fact into knowledge/pipeline/ is a separate
  anonymised, cited, kb-reviewed `kb` request.

## Content contract (verified against code and the MIG-35/36 packets, never memory)

Sources: DossierEvidence.java, DossierEvidenceReport.java, DossierReader/Validator/Readiness.java, ExportMetadata*.java,
model/ExportProvenanceInput.java, model/ExportManifest.java, cli/ExportCommand.java; packets 2026-10-27-mig-35-p6a-
packet.md and 2026-10-27-mig-36-p6b-packet.md (R1–R9, hand-back decisions).
States and blockers, exactly:
- Packet: valid-attribution when document checks pass and at least one review claim is PASS; unavailable otherwise.
  A per-claim FAIL blocks only uses of that claim; an all-FAIL review makes the packet unavailable.
- Use: supported / superseded / unavailable / proposed-unavailable. In one `replaces` chain the latest supported node
  is current, earlier nodes superseded, later unsupported nodes proposed-unavailable; with none supported the root is
  unavailable. Independent roots are separate requirements. proposed-unavailable never blocks.
- Milestone: a section with any evidence use, supported or not, gets EVIDENCE_SCOPE_UNRESOLVED unless the milestone
  consumes an exact dependency of that section; a consumed exact scope with any use in state unavailable gets
  EVIDENCE_UNAVAILABLE. Both set complete and canWork false; approval stays recorded. A basis whose scope has any
  unavailable use (consumed or not) is reported stale, but that creates no STALE_BASIS blocker and does not make
  derived documents stale.
- Required by the cite rule (rule 1, checked by reading): a statement cites only a use that is supported for its
  exact revision. The checker blocks only sections and scopes that have uses; a revision with no use raises no
  evidence blocker, even if an older revision of the section had a supported use. A supported use lifts no other
  blocker.
- Diagnostics: every packet or use reason is a warning EVIDENCE_UNAVAILABLE (missing file, digest, review identity,
  FAIL, text/scope mismatch, missing PASS); shape errors in evidence events (unknown field, blank, URI path, bad digest)
  are INVALID_DOCUMENT; out-of-order events (no earlier proposal for the
  scope, no earlier registration, forking `replaces`), UNC/device and non-default-filesystem paths are INVALID_EVIDENCE.
- Sidecar: FileDigest states measured, unavailable, read-time-snapshot; issues warning EXPORT_ARTIFACT_UNAVAILABLE and
  EXPORT_ROLE_MISSING, sidecar only; failure leaves earlier outputs, no cleanup, exit 1.
Required statements: source kind is not a certainty ladder; owner-confirmed never becomes tenant-observed; export and
read timestamps are not versions; a successful API call proves no cache, idempotence or retry resilience; supported
evidence never approves, answers, waives a risk, or raises or bypasses the approved complexity cap, which stays valid
without a concrete trigger; an accepted risk reopens only by `risk-reopen` with trigger new-evidence or
requirement-change; byte and reviewer-attribution checks are not source authentication or runtime proof; reviewer
independence is attributed, not authenticated; the sidecar records caller-supplied identity, not a running build or
loaded skill. Links: "any path component Java reports as a symbolic link or other (reparse) entry" makes a dossier
packet or review unavailable, an opt-in export source or descriptor fail, a supplied artifact unavailable, and an
alias-unresolved artifact plus any existing destination fails the whole preflight; cloud placeholders may be
reported as reparse entries — not tested. Existing pre-v3 PoC records stay context with their limitations; they
support a cite only once packaged as a new packet (sourceLocator to the record, sourceKind as it really is,
observedAt the record's own stated time or null, never packaging time), reviewed, registered and used.
Version-role mapping: export-label=exportLabel, package-release=packageRelease, bundle-version=bundleVersion,
target=targetVersion, design-time=designTimeVersion, deployed=deployedVersion; legacy-installed sidecar-only.
TenantKindTest scans skills/: avoid tenant-kind phrases (e.g. "tenant export", "customer tenant", "trial").
The docs authorize no tenant experiment.
