## Behavior and exact public API (draft for hand-over)

Existing export without the new option behaves exactly as before. With --provenance-input descriptor.json,
strictly load descriptor before writing outputs, then export original inventory/Markdown/Jira, then write
<base>.provenance.json. Use actual paths returned by ScaService, including .jira.txt; no guessed suffix reconstruction.
Before reading SCA or writing any output, opt-in preflight checks source/descriptor boundary and all4planned destinations.
ScaService may expose package-private List<Path> documentationPaths(String sca,String format,Path dir), sharing its
existing DocFormat selection/path construction with documentation(). Inventory/sidecar paths use the existing basename.
New helper public static void ExportMetadata.preflight(Path source,Loaded descriptor,List<Path> destinations) throws IOException
rejects unsafe output directories/files, collisions among destinations and collisions against source/descriptor/supplied
artifacts, using normalized lexical identity and Files.isSameFile for existing safe regular files (hard-link aliases too).
Never follow supplied link/reparse components to test identity. If any such artifact exists, all4destinations must be
nonexistent: otherwise fail before any write because alias safety is unresolved. Lexical collisions always fail.
New safe destinations still permit unavailable linked artifacts with diagnostics. Alias-check I/O failure prevents
overwrite before writing. This protects existing input files, not concurrent filesystem mutation (no transaction claim).
Preflight takes original SCA path explicitly, not a guessed path from ScaSource metadata. No new checks in legacy mode.
Report full sidecar, diagnostics and actual file paths. Do not claim atomic export: if sidecar writing fails after
legacy outputs, return failure through existing error handling and leave already written outputs visible.
Existing "Written" printing of the three legacy outputs is unchanged (documentation() writes MD and Jira before either
path is printed); the sidecar "Written" line is printed only after its write succeeds.
Supplied artifact unavailability/missing roles produces persisted manifest issues and CLI success; issues are only in
the sidecar, not a new stderr stream. Malformed descriptor, unsafe/colliding destination, output or sidecar I/O failure
uses existing CLI failure behavior. Do not print a sidecar path as written before that write succeeds.

New model.ExportProvenanceInput(int formatVersion,List<ArtifactInput> artifacts,List<VersionObservation> versions), nested:
- ArtifactInput(String role,String label,String path)
- VersionObservation(String role,String subject,String value,String sourceKind,String locator,
  String sourceSha256,String observedAt,String scope,String limitations)
New model.ExportManifest(int formatVersion,ScaInventory.Generator generator,String outputCreatedAt,
ScaInventory.ScaSource source,FileDigest descriptor,List<FileDigest> outputs,List<FileDigest> suppliedArtifacts,
List<ExportProvenanceInput.VersionObservation> versions,List<Issue> issues), nested:
- FileDigest(String role,String label,String path,String sha256,String state)
New migration.ExportMetadata:
- public static Loaded read(Path descriptor) throws IOException
- public static ExportManifest create(ScaInventory inventory,Loaded descriptor,List<Path> writtenOutputs) throws IOException
- public record Loaded(String descriptorPath,String descriptorSha256,ExportProvenanceInput input)
Loaded captures absolute normalized descriptor path, exact bytes' SHA256 and typed input in one read. create uses
that immutable input snapshot and read-time digest, never pretends to hash changed descriptor bytes later. It does
not re-read descriptor. Explicit supplied artifact files and written output files are hashed at create time.
No automatic scan of Git/HEAD, runtime classpath/JAR or skill directories; callers supply artifacts explicitly.

Input/output version1. New lists defensive immutable, null→empty only for programmatic constructors; strict JSON
requires both arrays and rejects null entries. Scalars null explicitly serialized. Public Loaded is immutable;
its identity is attributed to the reader/caller, not authenticated merely because a record can be constructed.
Output generator and source are retained inventory.generator/source verbatim; generator.readAt remains inventory
reading time. outputCreatedAt is manifest-generation time sampled during create, not filesystem creation time,
original export date or package release. It may exist even if the caller never writes the returned manifest.
Reports.java may extract/reuse its timestamp helper without changing generator() output fields/meaning.

## Descriptor and file rules

Strict JSON fields, duplicate keys/trailing tokens/unknown fields and unsupported format fail IOException before
CLI outputs. artifacts permits role build or skill, nonblank label/path. Paths resolve relative to descriptor;
absolute local files allowed. Lexical URI/UNC/device/non-default provider violations are descriptor IOException before
export. Syntactically valid local missing/inaccessible/nonregular/link targets are unavailable artifacts, except the
explicit destination overwrite-safety rule above. Inspect existing components NOFOLLOW before file bytes are read.
Portable Java does not authenticate mapped-volume physical locality; no network-isolation claim.
Malformed path syntax is descriptor error before export. Missing/inaccessible/nonregular/reparse supplied files
produce sha256=null,state=unavailable and Issue diagnostics; never silently drop the supplied entry.
Measured files have state=measured, SHA256 of actual bytes. Paths in manifest are resolved absolute paths;
labels and artifact roles preserved in source order. They describe caller-supplied artifacts, not proven running
binary or loaded agent skill. Missing build/skill roles have explicit diagnostic, not fabricated identity.
Descriptor FileDigest role=descriptor,label=descriptor filename,state=read-time-snapshot. Output files role=output,
label=filename, state=measured. Hash outputs only after writing; missing/unreadable output throws IOException.
Manifest never hashes itself. Do not mutate any input file or delete partially written output on failure.

VersionObservation role exactly export-label/package-release/bundle-version/target/design-time/deployed/legacy-installed.
subject,value,locator,scope,limitations nonblank; sourceKind one of export/documentation/derived/owner-confirmed/
tenant-observed, sourceSha256 nullable valid hex digest, observedAt nullable valid dossier date/timestamp.
Retain observations verbatim in order, including multiple observations of same role/subject; do not deduplicate,
choose newest or overwrite a deployed observation with a downloaded release/Bundle-Version. No inference from
timestamps, inventory SoftwareComponent release or one role to another. Legacy-installed stays legacy-installed;
owner-confirmed stays owner-confirmed. These are attributed observations, not validator-authenticated runtime facts.
Actual original SoftwareComponent manifest fields remain available separately in retained source metadata.

## Revision3 binding rules

Precedence: these rules resolve preflight r2 FAIL1–4 and its notes; they win over conflicting wording above.

R1 owner. Preflight is public static ExportMetadata.preflight(Path source,Loaded descriptor,List<Path> destinations)
throws IOException, beside read/create. The CLI calls read, then preflight, then the existing export, then create.
Destinations are exactly the 4 planned absolute paths: inventory .json, .md, .jira.txt (from ScaService
documentationPaths) and <base>.provenance.json. Legacy mode (no --provenance-input) calls none of these.

R2 collision scope. Inputs are source SCA, descriptor and every supplied artifact path; outputs are the 4 destinations.
Failures (IOException before any read of SCA bytes or any write): output==output, or output==any input, compared
first lexically (absolute normalized path) and then, when both exist as link-free regular files, by Files.isSameFile.
Input==input (artifact==source, artifact==descriptor, descriptor==source, two artifacts on one path) is allowed and
not a diagnostic: each artifact entry is recorded and hashed on its own, in descriptor order.

R3 link/reparse and "exists". A NOFOLLOW component walk (as DossierEvidence.read: absolute path, default filesystem,
each existing component read with NOFOLLOW_LINKS, stop at the first missing component) classifies every path.
- Source SCA (opt-in only): any symbolic-link/other component or non-regular target fails preflight. Legacy unchanged.
- Descriptor: same walk inside ExportMetadata.read before reading bytes; violation is descriptor IOException.
- Destinations: output directory components and an existing destination entry must be link-free; an existing
  destination must be a regular file, else preflight fails. Missing directories are created afterwards as now.
- Supplied artifact: "alias-unresolved" when its walk meets a symbolic-link/other entry (including a dangling link
  or a junction to a missing target). If any artifact is alias-unresolved, no destination may have any entry on disk
  (checked NOFOLLOW); otherwise preflight fails. A plain missing artifact (no entry at its first missing component and
  no link before it) is not alias-unresolved. Alias-unresolved and missing artifacts still become unavailable entries.

R4 diagnostics. Manifest issues use existing model.Issue with severity "warning", location null, source = the
artifact's resolved absolute path (or null for a missing role), message naming role, label and cause:
- EXPORT_ARTIFACT_UNAVAILABLE: one per unavailable supplied artifact entry (missing, inaccessible, non-regular,
  link/reparse); the cause appears in the message, not in separate codes.
- EXPORT_ROLE_MISSING: one per role among build and skill that has no artifact entry at all.
Order: artifact issues in descriptor order, then missing roles in order build, skill. No other new codes.

R5 JSON and formats. New records (ExportProvenanceInput*, ExportManifest*) use @JsonInclude(ALWAYS) like
DossierEvidenceReport so their own null scalars are explicit; nested existing types (ScaInventory.Generator,
ScaSource, Issue) keep current NON_EMPTY behaviour. outputCreatedAt is ISO-8601 UTC truncated to seconds, the
format of Reports.generator(); the interval test compares against the start instant truncated to seconds.
observedAt accepts null or a value DossierReader.timestamp accepts, except "unknown", which is rejected.
VersionObservation roles map to MIG-35 Versions fields: export-label=exportLabel, package-release=packageRelease,
bundle-version=bundleVersion, target=targetVersion, design-time=designTimeVersion, deployed=deployedVersion;
legacy-installed is new, with no MIG-35 counterpart. MIG-37 documents this mapping.

R6 partial output. "Acknowledges existing partial output" means the earlier "Written" lines and the files remain on
disk, the existing "Error: ..." message and exit 1; no new message, no cleanup.

R7 Windows fixtures without privilege, named so no case is skipped by assumption: junction via `cmd /c mklink /J`
(precedent DossierEvidenceTest), hard link via Files.createLink, sidecar write failure via an existing destination
that passes preflight but is set dos:readonly. If junction creation fails, that case is ENVIRONMENT_BLOCKED in the
handback, never asserted green; symbolic links are not required.

R8 preflight r3 notes (binding). An I/O error during any walk (e.g. access denied on a parent) makes an artifact
alias-unresolved, never plainly missing; for source/descriptor/destination it fails preflight. preflight normalizes
Loaded.descriptorPath to absolute before comparison. Opt-in CLI tests assert exit 1 and an "Error:" line, not the
legacy "SCA file not found" text. Tests that set dos:readonly clear it in finally.
