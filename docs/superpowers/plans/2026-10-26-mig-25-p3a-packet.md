## Source findings that govern this design

MoinIndex already retains parsed partition elements/links. Do not add a second XML parser.
The existing parser omits MOIN-internal attributes, normalizes local: prefixes and collapses
repeated map keys; it has no raw XML bytes/line offsets. Name this parsed-source evidence,
never a byte-exact raw snapshot. The original SCA source digest remains in ScaInventory.
MoinIndex.get selects the first duplicate ID; the new evidence resolves against every element
occurrence in the retained partition lists. firstElements drops missing IDs and cannot be
the source of evidence links. Preserve duplicate links and occurrences.

ScaInventory.SCHEMA_VERSION0.1 is shared by IntegrationQuery; leave it unchanged. Independently
version the new extension. Existing Process/Node/Flow/Mapping fields and meanings stay intact:
legacy true-only default/terminate and false-only enabled projections remain as they are.
The source extension preserves explicit false/true/missing/other strings separately.

Observed neutral source tokens (target/mig-p3-raw-metadata-scout.log):
Galaxy.Workflow.MultiInstanceLoopCharacteristics has sequential=false and flowCondition=all.
Keep exact SAP spelling EmbeddedScopeContainsLoopCharcateristics, f=loop,s=EmbeddedScope.
MILoopCharacteristicsContainsExpression has f=expression,s=loop; current-item and completed-
iterations associations have f=DataObject,s=loop. All names carry Galaxy.Workflow prefix.
Only these raw declarations were observed; synthetic true/unsupported/missing variants do
not prove runtime support. This slice retains facts without interpreting loop execution.

## Public extension — draft, review at hand-over

Add fourth BpmComponent component `BpmSourceEvidence sourceEvidence`; keep the existing
three-argument constructor delegating with null. Null means evidence unavailable, not a
complete empty model, and remains omitted from JSON under the existing inclusion policy.
New inventories from BpmReader receive the extension. Old JSON lacking it deserializes to null.
This preserves old constructor calls and field meanings, not binary record patterns or every
strict old JSON consumer. Document additive output compatibility honestly.

New public model record and nested records, component order exact:

- `BpmSourceEvidence(int formatVersion, String selectionVersion,
  List<String> indexedPartitions, List<String> processPartitions,
  List<Element> elements, List<Link> links)`; constants1 and `bpm-source-v1`.
- `Locator(String archive, String partition, int ordinal)`; ordinal is one-based occurrence
  in that partition's element or link list, not a line number. Archive is BpmContext.sourceArchive.
- `Element(Locator location, String id, String metaclass, Map<String,String> attributes,
  Map<String,String> texts, Map<String,List<String>> values, List<Property> properties)`.
- `Property(String key, String value)`; retain each entry of the parsed properties map in
  encounter order, including a null key or value. Do not turn a null key into the string null.
- `Candidate(Locator location, String metaclass, boolean included)`; included means a full
  Element payload is selected in this evidence object.
- `Endpoint(String id, String resolution, List<Candidate> candidates)`;
  resolution is unique/missing/ambiguous for candidate count1/0/>1.
- `Link(Locator location, String association, Endpoint first, Endpoint second)`;
  first and second retain the parser's normalized f/s strings and direction.

Every collection, including maps and lists nested in values, is a deeply immutable snapshot.
For a selected element's null property key, retain Property(null,value) and warn
BPM_SOURCE_PROPERTY_KEY_MISSING with element occurrence and property entry index. Preserve a
null value with a valid key without fabricating content. The export must remain serializable;
neither reject the whole export nor silently omit malformed property evidence.
Preserve encounter order from MoinIndex.partitions (LinkedHashMap) and source element/link lists;
preserve source map iteration order when copying. Retain null/blank parsed endpoint IDs as
missing without inventing identifiers. New extension/nested records serialize empty collections
and nullable fields explicitly; only the enclosing BpmComponent's absent extension is omitted.

## Exact selection rule bpm-source-v1

Selection is a documented subset, not a completeness assertion about the export or runtime.
indexedPartitions lists all actually indexed partitions in encounter order; processPartitions
lists ALL indexed paths starting src/bpmn/ and ending .bpmn in index encounter order, including
partitions that ProcessReader cannot interpret (for example, no Collaboration). This is the
existing path predicate, not the sorted list of successfully constructed Process records.
The existing processes list keeps its own sorting and filtering unchanged. .diagram remains
excluded from indexing by the reader.

1. Original seed occurrences: every element in a selected process partition (including unknown
   metaclasses), plus elements anywhere whose metaclass starts Galaxy.Workflow., Galaxy.Mapping.
   or Galaxy.Rule., or equals Galaxy.ProcessSupplements.NotificationActivity.
2. Select every link occurrence in a process partition. Outside process partitions select a
   link if its association begins one of those three prefixes, or either endpoint ID matches
   any original seed ID. Preserve links whose two endpoints are missing. Do not deduplicate.
3. Resolve selected-link endpoints against ALL indexed element occurrences, including duplicate
   IDs within one partition. Candidate order is partition/element encounter order. Missing and
   ambiguous endpoints stay explicit; do not fall back to names or first-match selection.
4. Add full supporting Element payloads for any endpoint candidate whose metaclass equals
   XSD1.key.QName or properties.PropertyBag. Other non-seed candidates remain boundary references
   with included=false. Do not recursively expand links of these new supports or WSDL/XSD trees.
5. Emit selected elements once per occurrence, in original encounter order, then selected links
   in their original order. Candidate.included uses this final selected-element set.

An empty result means only that this rule found no facts. Distinguish payload not selected
(unique candidate included=false), endpoint missing, and endpoint ambiguous. Mapping evidence
must retain owner→mapping→root part→child part→QName/expression identities; flattened Assignment
targets or Expression.reads names cannot replace this identity chain.

For each selected link's missing endpoint emit warning BPM_SOURCE_REFERENCE_UNRESOLVED; for
ambiguous endpoints BPM_SOURCE_REFERENCE_AMBIGUOUS. Include association, f/s side, original ID
and partition/link ordinal in diagnostic evidence. Use existing IssueLog/ScaInventory.issues;
do not reject the entire inventory or invent a resolved target. Duplicate-ID legacy diagnostics
remain unchanged. No warning solely because a unique candidate's payload was not selected.
Include occurrence identity and f/s side in diagnostic message or location, not source alone:
IssueLog deduplication ignores source. Repeated bad link occurrences and both missing sides
must remain separately visible diagnostics.
