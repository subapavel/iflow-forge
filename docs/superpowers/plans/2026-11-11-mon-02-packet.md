## Acceptance spec

The interfaces, field order, required-field defaults, record shapes and test list are those of plan
Task MON-02, "Interfaces" and "Step 1", read together with F-17. Additionally:

- Test server: an `io.poxray.po.FakePo` already exists in core tests; the monitoring test server is a
  new class `io.poxray.monitoring.FakeMonitoringPo` (JDK `com.sun.net.httpserver.HttpServer` on port
  0) that records every request (method, path+query, headers, body) and serves a configured status,
  headers and body. Reused by MON-03..06 (core already builds a test-jar).
- Envelope: SOAP 1.1 (`http://schemas.xmlsoap.org/soap/envelope/`), body child `getMessageList` in
  `urn:AdapterMessageMonitoringVi`, its children `filter` and `maxMessages` and every nested element
  in the namespace F-17 Appendix A/B/C gives for the declaring type. Tests parse the request body
  with a namespace-aware DOM and assert by namespace URI + local name, never by prefix or string match.
- `Message.flags` / `Message.durationMillis` as the plan states; `parsesMessagesAndKeepsRaw` also
  asserts one flag (`restartable` true) and `durationMillis`.
- Required filter fields always present with the plan's defaults; optional unset fields absent;
  `archive` set true is sent as `true`.
- Logon page with HTTP 200 (body contains `j_username` and `j_password`) → `authentication failed`
  (Review Focus 2). A 200 body that is neither SOAP nor logon page → `MonitoringException` naming
  "unexpected response", with the first 200 characters of the body.
- SOAP fault: parse the fault detail per F-17 Appendix D (`<op>_com.sap.aii.mdt.server.adapterframework.ws.OperationFailedException`
  with children args, code); message contains the `faultstring`, the code and the args.
- XML parsing: namespace-aware, `FEATURE_SECURE_PROCESSING` on, DOCTYPE disallowed; a test serves a
  response with a DOCTYPE/external entity and expects `MonitoringException`, not a resolved entity.
- `PoHttp` extraction: `PoClient` keeps its exact behaviour; all existing `PoClientTest` tests stay
  unchanged and green.
- No write operation names anywhere in `src/main` (the guard test itself is MON-04).
