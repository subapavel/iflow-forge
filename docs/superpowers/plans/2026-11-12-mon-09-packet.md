# MON-09 packet — XI header check reads only the start of a part

Date: 2026-11-12 · Row: MON-09 · Owner request 2026-11-12 ("tak to oprav") · builds on MON-08 (32729ec)

## Why

`PayloadPart.isXiHeader()` (MON-08) parses the whole part with the JDK DOM to learn its root element.
`MessagePayload.defaultPart()` calls it per part, and MCP `message_payload` without `part` repeats it
on every page call. For a large payload that is a full parse per page to read one start tag.

## Acceptance spec

A. `PayloadPart.isXiHeader()` decides from the document element alone, read with StAX
(`javax.xml.stream.XMLInputFactory`, namespace-aware) and stops at the first start element:
- `true` only for a text part (`text != null`, not blank) whose first start element is `Envelope`
  in `http://schemas.xmlsoap.org/soap/envelope/`.
- A DTD event before the root → `false`. `SUPPORT_DTD` false, `IS_SUPPORTING_EXTERNAL_ENTITIES`
  false, `ACCESS_EXTERNAL_DTD`/`ACCESS_EXTERNAL_SCHEMA` empty; nothing is ever fetched.
- Any `XMLStreamException` or `RuntimeException` before the root (malformed prolog, unbound prefix
  on the root, non-XML text) → `false`. Never throws. The reader is closed.
- Content after the root start tag is not read and does not change the answer.
- Seam for the test: package-private `static boolean startsWithSoapEnvelope(java.io.Reader)`;
  `isXiHeader()` delegates to it with a `StringReader`.

B. Architect's call (behaviour change against MON-08): a part whose root is a SOAP envelope but whose
rest is truncated or followed by a second root now counts as an XI header. Reason: the rule picks a
default part to show, it does not validate documents; reading the whole part to validate is the cost
the owner asked to remove. An unbound prefix on the root stays `false` (it is decided at the root).

C. Nothing else changes: `defaultPart()`, CLI, MCP, JSON shape (`@JsonIgnore` stays), descriptions.
The DOM builder and its imports are removed from `PayloadPart`.

## Tests (red first)

- `PayloadPartTest` changed: `malformedXmlIsNotAnXiHeader` — the "unclosed" and "two roots" cases move
  to a new method `onlyTheRootIsRead` that expects `true` (reason: B); "unbound prefix" stays `false`;
  add "garbage before any element" (e.g. `not xml <a/>`) → `false`.
- New `startsWithSoapEnvelopeReadsOnlyTheStart`: a counting `Reader` over a SOAP envelope root
  followed by ≥ 1 MiB of body; result `true` and characters read < 64 KiB.
- New: the same over a non-envelope root followed by ≥ 1 MiB → `false`, read < 64 KiB.
- `doctypeIsNotAnXiHeaderAndResolvesNothing` unchanged and still green.
- All other `PayloadPartTest`, `MessagePayloadTest`, `MessagesCommandTest`, `MessageToolsTest`
  unchanged and green.
