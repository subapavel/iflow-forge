# MON-08 packet — default payload part chosen by content, not position

Date: 2026-11-11 · Row: MON-08 · Finding: `docs/findings/F-18.md` (XI header part) · Spec §9 ·
builds on MON-07 (d078555)

## Why

MON-05 (CLI `payload`) and MON-06 (MCP `message_payload`) pick the default part by position:
`parts > 1 → part 1`, assuming part 0 is the XI header. On QA, `getMessageBytes` returned no XI
header part in 40 messages (one part each, the application document). With an attachment the
positional rule would skip the main document.

## Acceptance spec

A. Core (`io.poxray.monitoring`), one rule for both front ends *(architect's call)*:
- `PayloadPart.isXiHeader()` — `true` only for a text part (`text != null`) whose document element
  is `Envelope` in namespace `http://schemas.xmlsoap.org/soap/envelope/`. Parsed with the JDK DOM,
  namespace-aware, DOCTYPE disallowed and external entities off; any parse failure, a base64 part,
  or another root → `false`. Never throws.
- `MessagePayload.defaultPart()` — `int`: the index of the first part that is not an XI header;
  `0` when every part is one; `-1` when there are no parts.

B. CLI `MessagesPayloadCommand` and MCP `MessageTools.payload` use `defaultPart()` when no `part`
is given; an explicit `part` is unchanged. Help text and the MCP tool/argument descriptions say
"the first part that is not an XI header (SOAP envelope)" instead of "first part after the XI
header part". Nothing else changes (paging, errors, saving).

C. Tests (red first):
- core `PayloadPartTest` / `MessagePayloadTest` (new): one part → 0; SOAP-envelope header + main →
  1; main + attachment → 0; header + main + attachment → 1; only a header → 0; no parts → -1; an
  `Envelope` root in another namespace, malformed XML, a DOCTYPE-bearing text and a base64 part are
  not headers (and the DOCTYPE case does not resolve anything).
- CLI `MessagesCommandTest` and MCP `MessageToolsTest`: a new method each where a two-part payload
  main + attachment (no header) prints/returns part 0 by default, and header + main returns part 1.
- Existing tests that assumed "≥ 2 parts → part 1" with a fixture whose part 0 is not a SOAP
  envelope have a wrong expectation under F-18: the test-author may fix the fixture (make part 0 a
  real SOAP envelope) or the expectation, naming each changed method and the reason.
