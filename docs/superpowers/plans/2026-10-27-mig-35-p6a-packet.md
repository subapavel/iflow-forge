## Architectural decision

Introduce opt-in dossier v3 evidence-register/evidence-use events. They validate a local packet's exact claim,
scope, file digest and attributed independent review; they never answer questions or approve decisions automatically.
PoC results enter existing question-answer/proposal/scope-basis events explicitly, and evidence-use supports only
the exact declared claim/scope. No second answer workflow and no inference that an unavailable packet was valid before.
Original events/files remain unchanged. Source kind, approval, observations and version roles remain separate.

## Compatibility and exact event shapes

Keep existing public DossierValidator.check/assess/markdown signatures. V1/v2 semantics and event fields unchanged.
V3 accepts all original v1/v2 events plus these exact fields (common id,type,at,source unchanged):
- evidence-register: packetPath,packetSha256,reviewPath,reviewSha256.
- evidence-use: scope,evidence,claimId,text,replaces.
scope is existing DossierReport.Dependency(decisionId,sectionId,revision,sha256), not section-only.
evidence names an earlier evidence-register event; replaces is null or an earlier evidence-use ID for the same scope.
Normalize SHA256 consistently with existing dossier scopes; no other fuzzy matching or text normalization.
Unknown/missing fields, invalid IDs/hashes/local paths, dangling event/scope references and illegal replacements are
structural errors under existing invalid-ledger rules. Source locators inside packet metadata are attribution only.
Read only the explicit packet/review files, resolved relative to dossier directory like existing snapshot paths;
absolute local files allowed, URI paths rejected. Reject UNC (both slash forms), Windows device/network namespaces
and non-default filesystem providers before any filesystem access. Before reading file bytes, inspect each existing
path component with NOFOLLOW_LINKS: reject symbolic links and other/reparse entries instead of resolving through them;
target must be a regular file. No sourceLocator crawl or remote API. Normal mounted/mapped volume locality cannot be
authenticated by portable Java; explicitly retain this environmental limit rather than claiming network isolation.
Synthetic tests cover UNC/device spellings without creating network resources and a local link/reparse fixture where
the platform can create it; if creation is unavailable, report that check ENVIRONMENT_BLOCKED rather than inventing PASS.
Support same-version baselines and upgrades1→2(existing),1→3,2→3 with same migrationId and unchanged event prefix.
No downgrades, history rewrite or implicit file migration. Without baseline retain HISTORY_NOT_CHECKED.

## Local packet/review documents

Strict JSON objects, formatVersion1, no duplicate keys/trailing tokens/unknown fields. Required keys below;
nullable metadata explicitly null, not guessed. Malformed/unreadable/changed documents are external evidence
unavailability (warning), not malformed dossier events. Original bytes are never modified.

PacketDocument fields:
formatVersion,id,author,sourceKind,sourceLocator,sourceSha256,observedAt,versions,limitations,kbDifference,claims.
sourceKind exactly export/documentation/derived/owner-confirmed/tenant-observed. id/author/sourceLocator/limitations/
kbDifference nonblank; sourceSha256 nullable valid digest; observedAt nullable valid dossier date/timestamp.
versions exactly exportLabel,packageRelease,bundleVersion,targetVersion,designTimeVersion,deployedVersion;
each nullable nonblank string. Preserve distinct fields; read/export timestamps never become versions.
claims nonempty, IDs unique. Claim fields id,text,scope,limitations; text/limitations nonblank, scope nonempty unique
full Dependency values. Packet claim scope resolves against known proposal snapshots at the registration prefix,
not future events or the completed ledger, and does not imply approval. Invalid packet/review dependencies, claim IDs
or review references are external warning/unavailability; only references declared in dossier events are structural errors.

ReviewDocument fields: formatVersion,packetId,packetSha256,reviewer,reviewedAt,claims.
All scalar fields nonblank/valid; reviewedAt dossier date/timestamp. Reviewer must differ from author after trim and
case-folding, an attributed separation only. No authentication or human authority proof is claimed.
ReviewClaim fields claimId,scope,verdict,limitations. Unique claimId, scope nonempty unique Dependency values,
verdict PASS or FAIL, limitations nonblank. References and every reviewed scope must exist in the packet claim.
To support a use: both actual file digests equal event digests, review names exact packet ID/digest, matching claim
has PASS for exact use scope, claim.text equals use.text exactly, and claim includes exact use scope.
Missing review, self review, changed hash, FAIL, unsupported formats, missing claim or scope/text overreach remain
unavailable/open claims with explicit reasons. Preserve valid parsed packet metadata even when review is unavailable.
Checking bytes and attribution is not verifying source authenticity, tenant execution, cache or idempotence.
Owner-confirmed never changes to tenant-observed; supplied deployedVersion remains attributed metadata, not a new
observation inferred by this validator. No cross-field version/source-kind promotion.

## Uses, replacement and scoped guards

Every structurally valid use remains visible, even unavailable. Without replaces it is required for its exact scope;
multiple uses cannot silently overwrite each other and all active requirements must be supported.
With replaces, it extends exactly one earlier chain's declared tail for the same full scope. Structural ancestry is
immutable and independent of file availability: proposed-unavailable tails may be replaced, competing successors/forks,
forward refs and cycles are errors. Independent roots are separate required claims, never merged by claim ID or time.
After file validation choose the latest supported node in each declared linear chain as the current requirement;
earlier nodes become superseded, later unsupported nodes proposed-unavailable. If none is supported, the root is
unavailable and later nodes proposed-unavailable. All source reasons remain visible even on superseded nodes.
This is current applicability selection, not an assertion of historical admission or permanent owner supersession.
Losing/restoring B or C in A←B←C never changes structural validity; only this chain's effective evidence guard changes.

External unavailability adds warnings plus scope blockers; existing structural ledger errors still invalidate all
readiness under P2. Do not weaken that rule globally. Apply evidence guard independently of whether a scope-basis
exists, and in design milestones too; missing basis must not bypass an explicitly registered evidence requirement.
basis status becomes stale if its exact scope has an active unavailable use. Scope-basis admission still validates
existing answer/reference rules without using mutable external evidence, so declared historical bases remain visible.
Likewise milestone-approve admission uses evidence-independent existing P2 evaluation. Mutable evidence guards apply
only to final projection, never turn a previously declared approval into INVALID_TRANSITION. Evidence IDs do not enter
existing approvalInputs. An otherwise current approved milestone retains approved=true and its approvalEventId while
unavailable evidence makes complete/ready/canWork=false; original P2 changes to answers/definitions still apply as before.
At final milestone evaluation check exact requiredScopes and connections against active uses. If a milestone has a
section with evidence requirements but no exact consumed Dependency for that section, block it with explicit
EVIDENCE_SCOPE_UNRESOLVED rather than guessing a revision. If it names a different exact revision, do not bind by name.
Unavailable evidence prevents ready/canWork for the affected scope; existing prerequisite propagation applies.
Unaffected scopes/bases/questions/risks/approvals remain unchanged. Supported uses remove only evidence blockers;
they never grant approval, answer a question, waive a risk, satisfy unrelated prerequisites or authorize operations.
No evidence-use means no new global blocker: free prose and legacy claims are not automatically inspected.
