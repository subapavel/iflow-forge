## Purpose and boundaries

Project retained integration evidence and explicit supplied design claims into a deterministic catalog.
Keep source identities, XML names, request/response/fault uses, dependencies, ownership and lifecycle
choices separate; carry P3 data provenance without promoting structural candidates to runtime facts.
Supplied metadata is attributed evidence, not a verified owner approval. There is no arbitrary document
parser or approval engine; P1/P2 remain authoritative for approvals and readiness.

## Source-derived catalog

Stable IDs by category and original ordinal: source:<kind>:<index>; resource IDs append :resource:<index>.
Never deduplicate by display name. Source artifact kinds: native-message-type, native-data-type,
external-definition, xml-resource, esr-message-mapping, esr-function-library, mapping-function.
Generate artifacts for MT, DT, ExternalDefinition, retained resources, MessageMapping and its local
functions and function libraries actually present; function artifact owner is its enclosing artifact ID.
Source evidence has kind export, source inventory, locator exact indexed inventory field, status observed.
Observed here means parsed input evidence, never runtime observation. Basis source for derived artifacts.
Source owner stays unknown except explicit containment. Retain input issues and unknown coverage.

Native MT contract uses XML namespace only when present and MT name as declared native message name;
ESR identity remains separate. No QName for absent XML namespace. DT/resources produce declaration
contracts from explicit XML declarations only; no external-message QName inferred from keys/name/unique root.
External messages each get separate contracts keyed by full preserved reference, linked to containing
definition; legacy definitions without messageReferences keep legacy message names visible as unknown
contracts with unknown QName and diagnostic. Do not synthesize native MT from external XSD.
Native DT XSD may be inspected through MIG-30 ContractResources; it stays a native DT artifact.
Native DT declarations are owned directly by that DT, flattened in document/declaration order; no extra
xml-resource artifact is synthesized for native DT XSD. Its XML dependencies attach to the DT with locators.
Source contracts disposition unknown until an explicit claim is provided; source presence is not approval.

Each service operation request/response/fault contributes a port use on the referenced contract(s),
participant identifies the service interface, operation is the original operation name, step is null.
Unresolved/ambiguous references stay visible with diagnostics, no first-match selection. Map endpoint
uses separately as mapping-input/mapping-output, not as service request requirements.
Expose MT->DT, DT uses, mapping endpoints and function-library references as dependencies.
Reference matching: prefer exact nonempty OID within type, then full key + matching version context;
legacy empty keys allow exact case-sensitive type/name/namespace plus available SWC identity only as
candidates. Missing context never proves uniqueness across conflicting versions. Return all candidates,
state resolved only for unique exact source identity, candidate for unique incomplete identity, ambiguous
for multiple candidates, missing for none. No inferred runtime wiring.

## Resources and import dependencies

Keep each actual resource separate, including nested XSD in WSDL. For every resource dependency emit
kind, namespace, original location, evidence and candidate IDs. Never fetch/read imports from filesystem
or network. Resolve supplied sourcePath + relative location lexically as URI paths against other supplied
sourcePaths, preserve case. A namespace alone never resolves an import; missing sourcePath/location
is unknown with diagnostic. No invented filenames for embedded source resources.
One matching path is candidate, several ambiguous, no matching path missing; record candidates without
claiming valid/complete XSD compilation. Even matched imports are not proof of complete deployable package.
Transitive dependency rows remain visible independently, so a missing leaf is diagnosed. Cycles do not
recurse forever; emit finite per-resource edges. No global import-complete success flag.

## Supplied claims and validation

Explicit supplied artifact IDs are prefixed claim: in report; resource IDs supplied-resource:. Require
nonblank unique IDs; duplicates remain distinct by ordinal suffix and diagnostic, never silently merge.
Allowed supplied target artifact kinds: shared-message-mapping, iflow-mapping, script-collection,
local-script, mapping-function, external-definition, xml-resource, native-message-type, native-data-type.
Evidence with nonblank source/locator/status and kind artifact-declaration or design-decision can support
a classification. Transport-only evidence (kind transport, including ProcessDirect) never classifies
mapping placement. Unsupported kind or missing supporting evidence yields kind unknown, preserves
the claim in diagnostics/evidence, and reports the limitation; basis supplied remains explicit.
These checks validate structure of supplied provenance, not authenticity or correctness of the source.

Contract disposition is preserved-external, proposed-internal or unknown. Supporting evidence required
for non-unknown disposition and explicit external-message QName claims. Keep those claims separate from
source contracts, never overwrite source XML names or transfer approval. Invalid disposition/QName claim
becomes unknown with diagnostic; never invent owner/consumer/default or replace an existing contract.
Artifact/resource owner references must resolve to one exact supplied ID or source artifact ID; unresolved
and duplicate targets are diagnosed. Existing catalog/proposal can be entered only as supplied evidence.
Port roles: request, response, fault, mapping-input, mapping-output, producer, consumer.
Value roles: input, default, api-response; retain original default text and named producer/consumers.
Do not turn api-response into input. Input/default/api-response is an attributed claim, not execution proof.
Missing producer for default/api-response, evidence, unsupported role or bad StepRef gets diagnostic.
StepRefs validate against exact ProcessKey and step ordinal from data; no name fallback, no changed P3.
Keep claims visible on errors; renderer labels unresolved or unsupported fields, never silently omits them.

## Revision 2 identity and evidence rules

These rules resolve first-preflight ambiguities and govern the preceding prose:
- Top-level artifact IDs use original category-list indices. Contained functions append :function:<index>
  to their owner ID; resource IDs append :resource:<index>. Native MT contract: <artifact>:contract.
  DT/resource declaration: <artifact>:declaration:<index>. External message: <definition>:message:<index>;
  legacy names: <definition>:legacy-message:<index>. Duplicate source identities keep ordinal IDs.
- Dependency candidates always contain artifact IDs, not declaration/contract IDs. Match identities first;
  multiple declarations do not make one DT artifact ambiguous. ifmextmes matches full inner message
  identity only, attaches ports to message contract candidates and targets containing definition artifacts
  for dependencies. Never attach an external-message port to all resource declarations.
- Unmatched ports produce diagnostics retaining reference, role, participant and operation. A DT endpoint
  may resolve its artifact without proving a specific declaration binding; retain dependency and diagnose
  unresolved contract binding rather than attach ports to every declaration.
- Supplied references use exact raw IDs or complete source: IDs. Output prefixes: claim: (artifact),
  claim-contract: (contract), supplied-resource: (resource). Uniqueness domains are separate. All duplicate
  occurrences append :<original-list-index>; raw references to duplicates remain ambiguous. Blank IDs use
  ordinal-only IDs and diagnostics. No silent merging or first match.
- ArtifactClaim.owner is descriptive text retained verbatim. ResourceBinding.ownerArtifact and
  ContractClaim.artifact are artifact references; unresolved/ambiguous values retain their original text
  in diagnostics and do not discard the resource/contract.
- URI matching uses URI.create(sourcePath).resolve(location).normalize() with no I/O, percent-decoding,
  case-folding or OS-path reinterpretation. Malformed/opaque references are diagnosed. Compare against
  normalized provided resource sourcePaths; several nested resources at one path deliberately remain
  ambiguous candidates. A single exact path is only a candidate, not proven schema import compatibility.
- Downgrades retain original kind/disposition/QName/role/owner/StepRef field and claim ID plus indexed
  locator in diagnostics; preserve original evidence. Source binding unknown is not identity failure.
- Snapshot logic belongs in input/report constructors. Optional model snapshot helper operations stay
  package-private and are called by those constructors, not by migration package code.
