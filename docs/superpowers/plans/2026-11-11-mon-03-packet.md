## Acceptance spec

A. Plan Task MON-03 as written: methods, records (`ValueResult`, `LogEntry`, `LogResult`,
`MessagePayload`, `PayloadPart`), `Mime.parts`, `KeyResolver` with `Resolution` (`Key`, `Ambiguous`,
`NotFound`), and its Step 1 test list (`MonitoringClientDetailTest`, `MimeTest`, `KeyResolverTest`).
Request children, their order and namespaces per F-17 Appendix B; `Locale` as F-17 Appendix C.
`MonitoringClient.call(op, xml)` / `Reply` from MON-02 are reused.

B. Carry-over from the MON-02 review (`target/mon-02/review-r1.md`, non-blocking items), now binding:
1. Honesty: a value the parser cannot read (number, date, boolean) is never silently turned into
   null/false. `SearchResult` gains `Map<String,String> otherFields` (last component) holding such
   raw values by element name, as `Message` does; same for `LogEntry` (`otherFields` last component).
   Test: `unparseableSearchResultValuesAreKept` (number `abc`, date `yesterday`, warning `maybe`).
2. Repeated mapped child in `Message` (e.g. two `status`): the first is mapped, every later one goes
   to `otherFields` as `status#2`; a nil (`xsi:nil="true"`) unknown child is kept in `otherFields`
   with value `null`-marker `"(nil)"`. Tests: `repeatedMappedChildIsKept`, `nilUnknownChildIsKept`.
3. Tests that pin MON-02 behaviour not covered yet (in a new `SoapEdgeCasesTest`):
   `soap200ContainingLogonFieldNamesIsNotAnAuthFailure` (a valid envelope whose attribute value
   contains `j_username` and `j_password` parses normally);
   `missingResponseElementIsUnexpected` (envelope with `<getMessageListResponse/>` only →
   `MonitoringException` naming `Response`);
   `non200SoapWithoutFaultIsReported` (HTTP 500 with an envelope and no Fault → message contains `HTTP 500`);
   `invalidKeyFaultNamesTheKey` (the plan's test; `InvalidKeyException` detail with args, code, messageKey).
4. Encoding: when `Content-Type` has no charset, the body's XML declaration encoding is honoured
   (test: ISO-8859-2 body with `č` declared only in `<?xml … encoding="ISO-8859-2"?>`); default UTF-8.
5. Escaping: request text containing characters not allowed in XML 1.0 (e.g. U+0001) is rejected
   with `MonitoringException` naming the field, never sent (test: `controlCharacterInFilterIsRejected`).

C. Review Focus 1 and 3 (plan) are covered by `KeyResolverTest.twoKeysAreAmbiguousWithBothCandidates`
and `MimeTest.declaredCharsetIsHonoured` / `binaryPartIsBase64`.

D. Key format: a value containing `\` is a key (plan); the key format is confirmed live in MON-07.
