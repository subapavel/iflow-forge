## Acceptance spec

A. Plan Task MON-05 as written: core `MonitoringSystems`, `SaveTarget`, `MessageArchive`; CLI
`MessagesCommand` group with the 11 subcommands, `TimeArg`, registration in `PoXrayCommand`; the
options, defaults and exit code 2 on ambiguity; the Step 1 test list — with the changes below.

B. Test seams (architect's call):
- `MonitoringSystems.resolve(explicit, env, poxrayHome)` is tested as a pure function (unit tests
  cover the env fallback). The CLI calls it with `System.getenv()` and
  `Path.of(System.getProperty("user.home"), ".po-xray")`.
- CLI tests (`@QuarkusMainTest`, in-process) set `user.home` to a `@TempDir` for the test and
  restore it afterwards; they write `<tmp>/.po-xray/systems/<name>.properties` pointing at a
  `FakeMonitoringPo` (core test-jar, already a CLI test dependency) and, where needed,
  `<tmp>/.po-xray/monitoring.properties`. They never read the real home.
- The plan's `searchWithoutSystemUsesEnv` becomes `searchWithoutSystemUsesMonitoringProperties`
  (env cannot be set in-process); the env branch is covered by `MonitoringSystemsTest`.

C. Output:
- Table: one line per message — local start time with zone (`yyyy-MM-dd HH:mm:ss XXX` in the JVM
  default zone; tests set the expected string from the same zone), status, sender → receiver
  (component and interface name), message ID, key; a final line `<n> message(s)` and, when the
  service reports more, `more messages exist — narrow the filter or raise --limit` (stderr).
- `--json`: `Json.write` of the core result record (raw response included).
- Ambiguity (`KeyResolver.Ambiguous`): list each candidate (key or `(no key)`, direction, receiver,
  status) on stdout, a hint to repeat with `--key` or `--direction` on stderr, exit code 2. A
  candidate without a key is shown but never printed as a usable key (MON-04 carry).
- `NotFound`: its reason on stderr, exit code 1. `MonitoringException`: its message on stderr,
  exit code 1, no stack trace.
- `payload`: prints the selected part's text (or base64) to stdout; part list with index,
  content-id, content-type, size on stderr; `--part` default = first part that is not the XI
  header (the first part when there is only one); non-multipart prints the raw bytes as UTF-8 text
  with the note on stderr.

D. Saving (spec §7): `--save <dir>` writes through `MessageArchive.save` after `SaveTarget.check`;
without `--save` nothing is written anywhere (test asserts the temp cwd and temp home stay
unchanged apart from the files the test created).

E. Context7 before Aesh code: group commands (`groupCommands`), repeatable options
(`@OptionList`), arguments (`@Argument`), exit codes from `CommandResult`. If Context7 is
unreachable or ambiguous, `javap` on the Aesh jar in `~/.m2` decides. Follow the existing
commands' style (`SearchCommand`, `PoService`).
