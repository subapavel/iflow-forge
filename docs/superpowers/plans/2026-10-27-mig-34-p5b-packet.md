## Entry points and exact behavior

New CLI CompareBehaviorCommand implements Command<CommandInvocation> using house style and injected ScaService.
Aesh command compare-behavior, generateHelp=true; required @Argument(paramLabel="comparison.json") String path;
@Option(name="json",hasValue=false) boolean json. execute delegates to ScaService.run, reads
BehaviorComparison.read(Path.of(path)), prints Json.write(report).stripTrailing() or
BehaviorComparison.markdown(report), returns CommandResult.SUCCESS. Register in PoXrayCommand only.
No wrappers reconstruct facets/alignments, follow embedded paths or interpret issue severity.

New PoXrayTools public String behavior_comparison(String inputPath), annotated
@Tool(name="behavior_comparison",description=<honest local comparison description>,
annotations=@Tool.Annotations(readOnlyHint=true,openWorldHint=false)); argument
@ToolArg(description="Local comparison JSON with embedded reports").
Return existing call(() -> json("behavior_comparison",BehaviorComparison.read(Path.of(inputPath)))).
Use existing complete-output spill contract unchanged. No new output truncation or shared helper changes.

Missing/unreadable/malformed input or incompatible embedded shape: core IOException; CLI stderr/exit1 via
existing ScaService.run, MCP ToolCallException via call. Representable semantic diagnostics: complete report,
CLI success. This is inspection, not an approval/readiness gate. MCP may write existing spill file only;
neither entry point changes input JSON/referenced source files or calls any remote API.
