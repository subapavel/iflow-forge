# Reading SAP PO ESR & Integration Directory — findings

Verified on PO 7.50 SP28 system `xipod` (`http://xipod.ppas.cz:54200`), 2026-10-09. These are unofficial support endpoints (no SAP guarantee), but PO is end-of-life, so change risk is low. Wrap them behind own abstractions anyway.

**Decision:** for both ESR and Directory use **SimpleQuery (discovery) + `read/ext` (object content)**. One transport, one object format (`p1:xiObj`). Directory WS API not needed for now. TPZ = optional second transport into the same `xiObj` parser (only for customers without online access).

---

## 1. SimpleQuery (discovery)

Endpoints: `/rep/support/SimpleQuery` (ESR), `/dir/support/SimpleQuery` (Directory).

### 1.1 Calling it programmatically
POST `application/x-www-form-urlencoded` to the same URL with form fields:
- `useXMLL=true`, `queryRequestXMLL=<generalQueryRequest XML>`, `responseXMLL=true`, `requestXMLL=true` (optional echo)
- `action=Start query`
- Directory also accepted: `qc=Default (for directory objects)`, `deletedL=N`, `syncTabL=true`, `changeL=true`, `userL=<USER>`, `xmlReleaseL=7.1`
- Response is an HTML page; the result XML is in `<textarea name="response">` (request echo in `<textarea name="request">`). Errors are in the page body ("An exception occured …").

Authentication: Basic auth. **Send Authorization preemptively** — SOAP/POST endpoints challenge separately from GET (browser showed a second login dialog). Role e.g. `SAP_XI_DISPLAY_USER_J2EE` for ESR read; Directory API needs `SAP_XI_API_DISPLAY_J2EE`.

### 1.2 Request XML (as generated by the page)
ESR example:
```xml
<generalQueryRequest>
  <types><type id="MAPPING"/><type id="TRAFO_JAR"/></types>
  <qc qcType="S" delMode="N" useSyncT="true" clCtxOnly="false">
    <clCxt consider="A" user="subapa"/>
    <swcListDef def="L"/>                 <!-- L = All newest SWCVs -->
  </qc>
  <condition><complex><elementary><single>
    <key>NAME</key><val><simple><strg>*</strg></simple></val>
    <op isCaseIns="false">LIKE</op>
  </single></elementary></complex></condition>
  <result>
    <attrib>RA_XILINK</attrib><attrib>NAME</attrib><attrib>NAMESPACE</attrib>
    <attrib>OBJECTID</attrib><attrib>VERSIONID</attrib><attrib>MODIFYDATE</attrib>
    <attrib>MODIFYUSER</attrib><attrib>TEXT</attrib><attrib>RA_LINK_LIST</attrib>
  </result>
</generalQueryRequest>
```
Directory: `<qc qcType="D" delMode="N" useSyncT="true" clCtxOnly="false"><clCxt consider="A" user="..."/></qc>`, condition e.g. `MODIFYUSER LIKE *`.

Rules learned:
- `condition` element is **mandatory** (error otherwise).
- Operator `IS_NOT_NULL` (and/or some result attribute combinations) caused **HTTP 500** in Directory — use `LIKE *`.
- Several types per request are fine (Directory test: AllInOne 260, Channel 325, Service 91, DirectoryView 84, ValueMapping 2 in one call).
- `IFLOW` is not in the Directory form type list but **works via XML request** (258 iFlows on xipod).
- Other form options: SWC scope (`qc`: all / non-local / local / all newest / this one + `swcL`/`swcV`), `underL` (underlying SWCs), `deletedL` N/D/B, change lists (`changeL`, `changeLOnly`, `userL`), sync tables.
- Available condition keys / result attributes depend on selected types ("Refresh depended values"); load them per type once.

### 1.3 Response XML
```xml
<queryResult>
  <headerInfo><rows count="609"/><cols count="9"/><colDef><def type="NAME" pos="4"/>…</colDef></headerInfo>
  <typeInfo><type id="XI_TRAFO"><keyElem name="NAME" pos="0"/><keyElem name="NAMESPACE" pos="1"/></type></typeInfo>
  <matrix><r>
    <c><simple><strg>…</strg></simple></c>          <!-- also <date>, <bin> (OBJECTID) -->
    <c><qref isMod="false" isInUnderL="false"><ref>  <!-- RA_XILINK -->
        <vc vcType="S" swcGuid="499c5b00…" sp="-1" caption="PPAS_OTE, 1.0 of ppas.cz"><clCxt consider="A" user="subapa"/></vc>
        <key typeID="XI_TRAFO" oid="fba7e488…"><elem>name</elem><elem>namespace</elem></key>
        <vspec type="4" id="<versionId>" deleted="false"/>
    </ref></qref></c>
    <c><array><ref>…</ref>…</array></c>             <!-- RA_LINK_LIST = referenced objects -->
  </r></matrix>
</queryResult>
```
- Key element count varies by type (`typeInfo/keyElem`), e.g. `ifmextmes` has 4.
- `RA_LINK_LIST` gives the dependency graph directly from the query.

### 1.5 Directory object types
`AllInOne` (ICO), `Channel`, `Service` (communication component), `Party`, `DirectoryView` (configuration scenario), `InboundBinding` (sender agreement), `OutboundBinding` (receiver agreement), `RoutingRelation` (receiver determination), `MappingRelation` (interface determination), `RoutingRule`, `P2PBinding`, `ValueMapping`, `AlertRule`, `AgencySchemObj`, `DOCU`, + `IFLOW` (XML only), `AEName`.

## 2. read/ext (object content)

ESR:
```
GET /rep/read/ext?method=PLAIN&TYPE=XI_TRAFO
    &KEY=<name>|<namespace>            (URL-encoded, elements joined by |)
    &VC=SWC&SWCGUID=<swcv guid, no dashes>&SP=-1&UC=true&release=7.0
```
Directory:
```
GET /dir/read/ext?method=PLAIN&TYPE=AllInOne&KEY=|CD1CLNT300|urn:…:spds|ApplicationStatus_Out||&VC=DIR&UC=true&release=7.0
GET /dir/read/ext?method=PLAIN&TYPE=Channel&KEY=|V3S_D|REST_RCV_StateUpdate&VC=DIR…
GET /dir/read/ext?method=PLAIN&TYPE=IFLOW&KEY=61f6edf602ed3acbaddbd96bfa1152e9&VC=DIR…
```
The "R" links in SimpleQuery HTML results have exactly this form.

## 3. `p1:xiObj` envelope (common to ESR, Directory, TPZ)
```xml
<p1:xiObj xmlns:p1="urn:sap-com:xi">
  <p1:idInfo VID="<version id>">
    <p1:vc vcType="S" swcGuid="…" sp="-1" caption="…"/>   <!-- S = ESR (SWCV), D = Directory -->
    <p1:key typeID="XI_TRAFO" oid="<object id>"><p1:elem>…</p1:elem>…</p1:key>
  </p1:idInfo>
  <p1:generic>
    <p1:admInf><p1:modifBy/><p1:modifAt/><modifAtLong/><p1:owner/></p1:admInf>
    <p1:lnks><p1:lnkRole role="…" kpos="…"><p1:lnk rMode="A|R"> vc + key </p1:lnk></p1:lnkRole>…</p1:lnks>
    <p1:textInfo> descriptions, per-label texts </p1:textInfo>
  </p1:generic>
  <p1:content> type-specific </p1:content>
</p1:xiObj>
```
- `rMode="A"` absolute ref (with SWCV), `"R"` relative (same SWCV / Directory).
- Identity across sources: (vcType, swcGuid, typeID, key elems) + OID + VID. Normalise SWCV GUID (Directory WS API uses dashes, ESR none).

### 3.1 Message mapping content (`XI_TRAFO`)
`<tr:XiTrafo xmlns:tr="urn:sap-com:xi:mapping:xitrafo">` with `tr:JdkVersion`, `tr:Multiplicity` (e.g. `1:1`), `tr:SourceParameters`/`TargetParameters`, and blobs `<tr:blob type="zip|jar|xml" zipped="true">!zip!<base64></tr:blob>`:
| Element | After base64 → zip → (inner zip) |
|---|---|
| `tr:MetaData` | entry `value` (zip) → `metadata`: XML `<mappingtool version="XI7.1">` — graphical logic (`transformation`, `brick`), local UDFs (`functionstorage`, `javaText`, `imports`, `globals`), test data |
| `tr:SourceCode` | `value` → generated Java source of the whole mapping (`com.sap.xi.tf._<name>_`) |
| `tr:ByteCodeJar` | compiled classes |
| `tr:AdditionalMetaData` | small XML |
Prefix `!zip!` / `!jar!` / `!xml!` must be stripped before base64 decoding. Use a central-directory based unzip (local headers use data descriptors).

### 3.2 Directory content
- **ICO** `typeID="AllInOne"`, key = `senderParty|senderComponent|ifNamespace|ifName|receiverParty|receiverComponent` (**namespace before name**, Directory WS API has name before namespace). Content `<AllInOne version="110">`: `SenderConnectivity`, `ReceiverConfigurations` (routing via `TRD_EXTRACTOR`, `TYPE=KO` = constant), `InterfaceDeterminations` (`MappingRequired`, `Multiplicity`), `ReceiverAssignmentList`, `ReceiverConnectivityList`, `NoReceiverBehaviour` (codes). `lnks` roles: `outboundInterface`, `senderOperation`, `senderChannel`, `receiver`, `IIF<n>` (receiver SI), `MAP<n>` (operation mapping), `receiverChannel`, `PARENT_FOLDER`.
- ICO generated from iFlow: description `Generated for dir://IFLOW/<id> '<name>'`, and **ICO OID == iFlow key elem**.
- **IFLOW** content: `<IFlow>` with `IflowName`, `IflowID`, `Runtime`, `Pattern` (e.g. `com.sap.tc.pattern.ico.migrate`), `FlowSpec` (EndPoints, FlowSteps, Connectors), `DataParts` (operation mapping, sender/receiver system with XI header and SI, Inbound/OutboundProcessing, ChannelReference, receiver determination, default receiver). `lnks`: `iflow_sender_sys`, `endp-external-channels`, `endp-systems`, `iflow-ae` (AEName). Not available via Directory WS API at all.
- **Channel** `cp:Channel` (`urn:sap-com:xi:xiChannel`): EngineType, ChannelDirection (I/O), Message/TransportProtocol, `ChannelAttributes/AdapterTypeData/Attribute(Name,Namespace,Value)`, `PipelineAttributes` (`PipelineConfig`: Position, ModuleName, ModuleType `L`, ModuleNs; `ModuleData/ModuleConfig`: params). Adapter type = `lnks` role `ADAPTER` → ESR `AdapterMetaData` (e.g. REST in SWCV SAP BASIS 7.50). Table attributes appear as attributes in the flat list.
- **Service** (business system/component), **DirectoryView** (folder/config scenario), **AEName**.

### 3.3 Environment-specific values (important for migration)
| Attribute | `dir/read/ext` | Directory WS API | Directory TPZ |
|---|---|---|---|
| URL (`URLPattern`), user (`HttpUser`), OAuth URLs | present | present | **missing** |
| Passwords / secrets | missing | element present, empty | missing |
→ credentials always need manual handling (placeholders → CPI security material).

## 4. Directory WS API (evaluated, not chosen)
- Services on xipod: IntegratedConfiguration(750)InService, CommunicationChannelInService, Sender/ReceiverAgreementInService, Interface/ReceiverDeterminationInService, BusinessComponent/BusinessSystemInService, ConfigurationScenarioInService, ValueMappingInService, AlertRuleInService, ChangeListInService. `PartyInService` → 404.
- Namespace `http://sap.com/xi/BASIS`; `Query` returns IDs only; `Read` accepts 0..n IDs (batch). ICO Read element `IntegratedConfigurationID`; channel Read element is `CommunicationChannelID` (`PartyID`, `ComponentID`, `ChannelID`).
- Pros: official, human-readable values (`Error Message`, `Constant`, `Local Enterprise Bean`). Cons: no OID/VID, no typed links, no iFlow.
- Code ↔ text mapping (if needed later): `IfNoReceiverFound 0` ↔ `Error Message`, `TRD_EXTRACTOR TYPE KO` ↔ `Constant`, `ModuleType L` ↔ `Local Enterprise Bean`, VirusScan code ↔ `Use Global`.

## 5. TPZ export format (offline transport)
- Zip (SDA). ESR: `softwaresubtype: ESRTPZ`, `metadata.esr.710` / `Metadata.properties` (swcv, sourcesystem, release, object count, isDeltaExport, transportID), `<name>.tpt`, optional `.dlt` (delta for target release 711 — identical XML, dedupe by VID). Directory: `systemtype=IBC 7.1`, `contenttype=changelist`, `swcv=000…`.
- `.tpt`: magic `00000000 dc358a91`; **last 8 bytes = catalog offset** (big-endian long). Catalog = XML `<catalog><segments><segment type offset length/>…<objectList>…`.
- Segment = 8-byte big-endian length + payload; some (header, catalog) have additional 8-byte CRC before XML.
- Segment types: `header`, `metaModel-PVC` (XSD), `metaModel-Model` (ESR: `nonXiObj` = SWCV definition incl. underlying SWCVs), `pvcVersionSet`, `modelGeneralData` (`p1:metaData`), per object `pvcElement` (400 B binary version record) + `modelElement` (**`p1:xiObj`**), `knownDevlines`.
- Directory individual export of ICO contains only the ICO; export of iFlow contains IFLOW + channels + services + folder (not the generated ICO).
- Deleted-object flag not found in XML (probably in binary `pvcElement`) — unverified.

## 6. Proposed snapshot (later phase)
1. Discovery (SimpleQuery) → list of (type, key, vc, OID, VID, links).
2. Fetch (`read/ext`) → raw `xiObj` stored unchanged; decoded blobs stored next to it.
3. Small index: type, key, OID, VID, outgoing links (role → target).
4. First useful output: inventory chain iFlow/ICO → channels → adapters/modules → OM → MM/archives, plus unused ESR objects.
