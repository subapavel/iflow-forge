- **Assumption in the document:** §7 item 2 ends phase 2 with "every version-gated feature (`versions/features.md` against the
  profile's installed versions) ... is on the open list"; §10 says "a feature the plan relies on that the tenant's version lacks

  answer was "present, no update" — eleven empty rounds of a one-question-at-a-time protocol; D-038 (b) already exempts
  `present in` rows, so two kinds of present feature were treated differently.
- **Severity:** minor — the intent (ask when the tenant's version lacks a feature or the version is unknown) is clear from §10;
  §7 item 2 is wrong only in listing the present features too.
- **Evidence:** spec L189–190 (§7 item 2), L292–297 (§10); `references/attributes.md` "Version-gated features" step 4;
