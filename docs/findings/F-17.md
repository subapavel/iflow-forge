# F-17 — AdapterMessageMonitoring contract: data types sit in other namespaces than §4 says

Date: 2026-11-11 · Task: MON-01 · Spec: `docs/superpowers/specs/2026-11-11-message-monitoring-design.md` §4, §9

- **Assumption in the document:** §4 places `AdapterFilter`, `AdapterFrameworkData`,
  `MessageSearchReturnValue` and `AuditLogEntryData` in `urn:com.sap.aii.mdt.server.adapterframework.ws`
  and `MessageInterface`, `MessageParty`, `BusinessAttribute`, `StatusDetail`, … in
  `urn:com.sap.aii.mdt.api.data`; faults are "`OperationFailedException` (code, args)".
- **How it fails in practice:** the served interface WSDL declares `AuditLogEntryData` in
  `urn:com.sap.aii.mdt.api.data`, and `BusinessAttribute`, `StatusDetail`, `Locale`,
  `IntegrationFlow`, `AttributeMetadata` in `urn:com.sap.aii.mdt.server.adapterframework.ws`. All
  schemas are `elementFormDefault="qualified"`, so a local element is in the namespace of the schema
  that declares it: a client built on §4 would write UDS `attributes` and `locale` children, and read
  audit-log and status-detail children, in the wrong namespace, and a namespace-aware DOM would find
  nothing. Further precision the builder needs (appendix): every response wraps its value in one
  `Response` element; arrays are wrappers of repeated items (`String` in `urn:java/lang`, …); the
  message flags are `BooleanAttribute` wrappers with a `value` child; fault details are
  per-operation elements in a fourth namespace; eight `AdapterFilter` children are required.
- **Severity:** major (the WSDL contradicts §4's namespace mapping; the mechanism, a hand-written
  namespace-aware SOAP client, stays).
- **Evidence:** anonymous WSDL GETs, no credentials, no operation call, saved under
  `local/<customer>/monitoring-probe/` (gitignored): `qa-service.wsdl` (HTTP 200, 1,666 B),
  `qa-binding.wsdl` (200, 15,840 B), `qa-interface.wsdl` (200, 74,397 B), `prod-service.wsdl`
  (200, 1,678 B), `prod-binding.wsdl` (200, 15,842 B), `prod-interface.wsdl` (200, 74,397 B); status
  log `probe-log.txt`. Line numbers below refer to `qa-interface.wsdl` unless stated.
- **Change made:** spec §4 namespace sentence corrected and the response/array/flag/fault shapes
  added in one paragraph; the fault child order corrected to (args, code[, messageKey]); the contract tables are in the appendix below. The plan's pinned
  `AdapterFilter` order (MON-02) matches the WSDL exactly (L121-167) and is not changed.
- **Spec edit:** "Changelog: 2026-11-11 F-17 — §4 namespace of each data type corrected from the
  served WSDL; response wrapper, array, flag and fault shapes added."
- **PROGRESS entry:** MON-01 marked `Deviation: F-17`
- **For the owner's review:** (1) MON-02 says "absent fields omitted", but `archive`, `dateType`,
  `nodeId`, `onlyFaultyMessages`, `retries`, `retryInterval`, `timesFailed`, `wasEdited` have no
  `minOccurs="0"` (L124-161); whether the server accepts them absent, or what neutral value they
  need, is not visible in the WSDL — the architect decided (plan MON-02): always sent, defaults
  false/0, checked on QA in MON-07. (2) The §9 points (`dateType`,
  status values, `version`, `logLocations`, unbounded time window) need operation calls and stay
  open for the live task; this probe made none.

## Appendix A — namespaces (all `elementFormDefault="qualified"`)

| Short | Namespace | Declares |
|---|---|---|
| OP | `urn:AdapterMessageMonitoringVi` | the 24 operation elements and `…Response`, and their children (L452-805) |
| WS | `urn:com.sap.aii.mdt.server.adapterframework.ws` | `AdapterFilter`, `AdapterFrameworkData`, `MessageSearchReturnValue`, `BusinessAttribute`, `AttributeMetadata`, `IntegrationFlow`, `StatusDetail`, `Locale`, `OperationFailedException`, `InvalidKeyException`, `Array*` of these (L107-322) |
| DATA | `urn:com.sap.aii.mdt.api.data` | `MessageInterface`, `MessageParty`, `AuditLogEntryData`, `BooleanAttribute`, `DurationAttribute`, `AttributeValue` (empty base), `ArrayOfMessageParty`, `ArrayOfMessageInterface`, `ArrayOfAuditLogEntryData` (L369-451) |
| JL | `urn:java/lang` | `ArrayOfString` (item `String`, L323-329) |
| FLT | `urn:AdapterMessageMonitoringWsd/AdapterMessageMonitoringVi` | fault detail elements (L335-368); also the WSDL/portType namespace |
| EXC | `urn:com.sap.exception` | `BaseException`, empty sequence (L806-810) |

Rule that follows: a child is in the namespace of the type that declares it, not of its parent
element. Example: `OP:getMessageList/OP:filter/WS:interface/DATA:name`; a string array is
`…/WS:messageIDs/JL:String`.

## Appendix D — faults (2c)

- Binding: each fault is `soap:fault use="literal"`, name
  `com.sap.aii.mdt.server.adapterframework.ws.OperationFailedException` or
  `…InvalidKeyException` (`qa-binding.wsdl`).
- Detail element: one per operation and fault, in FLT, named
  `<operation>_com.sap.aii.mdt.server.adapterframework.ws.OperationFailedException` (or
  `…InvalidKeyException`), wsdl part `errorPart` (L335-368, L844-846).
- `OperationFailedException` (WS, L111-120) extends EXC:`BaseException` (empty): args
  JL:ArrayOfString O, code int R. `InvalidKeyException` (WS, L267-275) extends it: args, code, then
  messageKey string O.

## Appendix E — binding and endpoint (2d)

`qa-binding.wsdl`: binding `basicBinding` of port type `AdapterMessageMonitoringVi` (FLT),
`soap:binding style="document"` over `http://schemas.xmlsoap.org/soap/http` (SOAP 1.1), 24
operations, every `soap:operation soapAction=""`, input `soap:body parts="parameters" use="literal"`,
output `use="literal"`; WS-Policy alternatives HTTP Basic and SSO2. `qa-service.wsdl`: service
`AdapterMessageMonitoring`, ports `basicPort` at `<url>/AdapterMessageMonitoring/basic?style=document`,
`sslPort` at `…/ssl?style=document`, `clientCertPort` at `…/clientCert?style=document`.

## Appendix F — QA vs PROD (3)

`qa-interface.wsdl` and `prod-interface.wsdl` are byte-identical (`cmp`): same 24 operations, same
type definitions. The binding and service documents differ only in the host of the
`wsdl:import` and `soap:address` locations (`diff` with the host stripped is empty; byte sizes differ
by the host length). No contract difference.
