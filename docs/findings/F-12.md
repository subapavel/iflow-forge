# F-12 — Source labels carried the tenant kind; the owner rules it irrelevant

Date: 2026-10-21 · Task: KB-14 · Spec: docs/superpowers/specs/2026-10-19-pipeline-knowledge-base-design.md §13 (and D-008)

- **Assumption in the document:** §13.1–13.2 name the two exports by where they came from ("SAP trial tenant", "tenant
  export"), and D-008 fixed the labels `2026-06-trial` and `2026-09-current`; the pages, `versions/`, `kb.sources` and
  279 cites in 62 knowledge pages carry those labels, and three pages describe an export by its tenant kind in prose.
- **How it fails in practice:** the owner states [owner, 2026-10-21] that the tenant an export came from carries no
  information: the pipeline packages are versioned by SAP and identical on every tenant, so "trial" in a label or a
  sentence misleads a reader into expecting a different behaviour. The first-real-run guide (MIG-18) had to describe the
  knowledge base by its package versions and could cite them only through a path that still says "trial".
- **Severity:** minor (naming; no mechanism changes, the fact base and every cite target stay the same files).
- **Evidence:** scout survey 2026-10-21 (KB-14 scratchpad): 279 label occurrences in 62 pages under knowledge/pipeline,
  prose sites versions/README.md:13–14, versions/2026-09-current/changelog-generic-pipelines-step02.md:19,
  knowledge/sources/README.md:9–10; no Checks rule guards a label or the words; `KnowledgeBase.DEFAULT_SOURCES` = the
  old label (L21); `SourcesAcceptanceTest` hard-codes the folder (L26).
- **Change made:** D-044. Labels become plain export dates `2026-06` and `2026-09` (`git mv`, every cite and path
  follows, `kb.sources` default follows); the tenant kind leaves every knowledge page, skill page and doc; a new Checks
  rule `tenantKind` keeps the words out of knowledge/pipeline and skills pages. The package versions of each label are
  stated in D-044 and in `versions/README.md`. History (DECISIONS rows before D-044, PROGRESS, findings, issues) stays.
- **Spec edit:** changelog line 2026-10-21 · F-12 · §13 labels are export dates without a tenant kind (D-044).
- **PROGRESS entry:** KB-14 marked `Deviation: F-12`
- **For the owner's review:** the label scheme `YYYY-MM` assumes at most one export per month; a second export in a month
  would need a day suffix (`2026-10-15`), which D-044 does not forbid. Rejected alternative: a label made of the four
  package versions (`1.0.7-1.0.4-1.0.3-1.1.1`), exact but unreadable in cites.
