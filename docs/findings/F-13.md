# F-13 — The intake asked the migrator for the wiring the artifacts already hold

Date: 2026-10-21 · Task: MIG-20 · Spec: docs/superpowers/specs/2026-10-20-migration-front-end-design.md §5, §6.3, §7 item 1

- **Assumption in the document:** §5 lists "ICOs around the process, including the ICO that runs before the BPM
  process" as an input the migrator produces with `po-xray ico -s -c -d both -o`, one dump per communication
  component the migrator names; §7 item 1 has the migrator name the target and the skill only list present and
  missing inputs; the quick start (MIG-19) therefore had the start prompt spell out the process, its EJB modules and
  its communication components by hand.
- **How it fails in practice:** the owner states [owner, 2026-10-21] that typing the components and ICOs is a step back
  behind what po-xray reads: the export catalog already carries every interface a process starts from or calls
  (`Interface.Usage` roles `start`, `intermediate`, `outbound`, `notification`, ProcessReader.java:217–249, 352–356),
  and the ICO inventory carries every sender interface (`Ico.sender.iface`) and receiver interface
  (`Receiver.interfaces[].targets[].iface`), so the ICOs before and after a process follow from the artifacts. A hand-typed
  list can miss an ICO or name the wrong component and the scenario narrows silently.
- **Severity:** major (the intake's input contract; no built mechanism changes, two helpers are added).
- **Evidence:** scout surveys 2026-10-21 (MIG-20 scratchpad): `bpm-inventory` reports steps and EJB roles only
  (BpmInventoryReport.java:13–20); `ico -c` is mandatory (IcoCommand.java:31–33); `IntegrationQuery.icos` lists every
  ICO of the system and filters by component after resolving (IntegrationQuery.java:98–122), so an all-ICO inventory
  costs nothing extra; the tpz path runs through the same connection (PoConnection.java:13–21).
- **Change made:** D-045. MIG-20 adds `ScenarioDiscovery` → `DiscoveryReport` (core), MIG-21 the CLI
  `po-xray discover` with the ICO dumps per found component, MIG-22 rewrites the intake input row, the start prompt
  and the quick start so the migrator names the customer, the system and the export directories only.
- **Spec edit:** changelog line 2026-10-21 · F-13 · §5 ICO row derived, §6.3 helper `discover`, §7 item 1 target by
  artifacts (D-045).
- **PROGRESS entry:** MIG-20 marked `Deviation: F-13`
- **For the owner's review:** one hop only in the first scope — an ICO whose receiver is itself another BPM process or
  whose sender is fed by a further ICO is listed as a component, not followed; the migrator can run `discover` again on
  that component's export. Matching is exact on interface name and namespace; an ICO that routes to the process through
  an operation mapping onto a different interface is reported as an interface without an ICO, not guessed.
