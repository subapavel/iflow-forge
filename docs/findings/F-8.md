# F-8 — The attributes helper and two knowledge pages derive `custom_exit` and `inbound_conversion` differently

Date: 2026-10-20 · Task: MIG-03 · Spec: docs/superpowers/specs/2026-10-20-migration-front-end-design.md §6.3; docs/OUTPUT-MODEL.md "Migration helpers"

- **Assumption in the document:** §6.3 says `po-xray attributes` returns "D-025 attributes derivable from the ICOs, with
  the field each value came from, and `?` where a question is needed". The rules were fixed in MIG-02 (OUTPUT-MODEL "Rules
  in short"): a non-adapter module on the sender channel → `custom_exit` pre; `AF_Modules/MessageTransformBean` on the
  sender → `inbound_conversion` custom, any other sender module is an exit.
- **How it fails in practice:** writing `references/attributes.md` (MIG-03) against the knowledge pages:
  migration/po-ico-to-pipeline.md:44 says `custom_exit` has no ICO field, the human decides; migration/variants.md:50 says
  every sender-side module but `CallSapAdapter` goes to the inbound conversion copy (human decides, default custom). For a
  sender channel with one custom module the helper answers `pre` / `none` where the knowledge base answers "ask, default
  conversion". The skill would carry a derived value that the pages call a decision.
- **Severity:** minor (the migrator sees the module list and the pages; no wrong artifact is produced).
- **Status:** closed by MIG-02b (D-032 implemented; the kb-reviewer found the same gap on the receiver side — conversion/README.md "Rules": outbound conversion or post exit — closed by D-033 in the same task; po-ico-to-pipeline.md:44 and references/attributes.md:27–28 updated).
- **Evidence:** kb-author hand-back of MIG-03 (two cites compared); skills/sap-po-migration/fixtures/icos-SND_SYS.json
  scenario (c) gives `custom_exit` pre for a SOAP sender with one module (target/mig-02-smoke2-attr.md).
- **Change made:** D-032: a sender-side non-adapter module other than MessageTransformBean makes both attributes a
  question — `inbound_conversion` `?` {none, custom} and `custom_exit` `?` {none, pre} with the question "conversion
  (Step03; variants.md default custom) or pre-processing exit?"; MessageTransformBean stays `inbound_conversion` custom;
  a receiver-side module stays `custom_exit` post. Scheduled as BACKLOG row MIG-02b (helper rule, tests, fixture
  expectation, OUTPUT-MODEL, po-ico-to-pipeline.md:44 wording "channel modules; sender module → question"). Until then
  `references/attributes.md` states both sources and tells the agent to open a blocking item. §6.3 stays as written.
